# v0.5 → v0.7 — Rolling Manual Test Plan

> **Scope**: a single rolling test plan covering the v0.5 → v0.7 strangler-fig
> arc (TS CLI → TS web server → TS ingestion pipeline). Originally
> "v0.5-manual-test-plan.md" for the v0.5.0 cut on 2026-05-27; renamed to
> "v0.7-manual-test-plan.md" to reflect that the same doc grows through each
> iteration's manual-verification surface and lives until v0.7.0 ships.
>
> **Update cadence**: iterations 24 (v0.6) and 25 (v0.7) each add a section
> covering their new surfaces (web server boot, ingestion-pipeline parity,
> Hono-vs-FastAPI response-shape checks, etc.) and re-tick the v0.5
> sections that still apply. Updating this doc is a tracked deliverable
> for both iterations — see plan.md.
>
> **Walked on every cut**. Each section's `Status` line is ticked when that
> section's checklist passes for the cut in question.
>
> **What this covers that the automated suite can't**:
>
> - Behaviour on a **clean macOS install** (no uv, no clone).
> - Interactive flows (`cerefox init`, prompts).
> - Cross-shell tab completion (bash, zsh, fish).
> - Per-MCP-client config writers against real client config files.
> - Three-way npm publish verification (mirrors the v0.4 first-publish
>   gauntlet checklist in Decision Log Q2 Part 3).
> - **v0.5.4+ round-trip verification**: spawn the target client and
>   confirm cerefox tools actually appear (the gap that let the v0.5.0–v0.5.3
>   configure-agent wrong-path bug ship).
>
> **Status as of v0.5.0 cut (2026-05-27)**: every Part landed; 105 TS tests +
> 587 Python tests green. v0.5.1–v0.5.4 patches added per-release sections
> covering bin-drop, soft-wrapper strip, paths precedence inversion, and
> configure-agent claude-code fix.

Each section has a `**Status**` line that gets ticked as the maintainer runs
through it before signing off a release. v0.5.x patches: only re-run the
sections that match what changed.

## 0. Environment matrix

The full surface lives on three matrices:

- **Runtime**: Bun ≥ 1.0, Node ≥ 20 (no LTS-of-LTS yet — Node 20 + 22 sampled).
- **OS**: macOS 14+ (primary), Ubuntu 22.04 (CI), Windows (not in scope for v0.5).
- **Install source**: `npm install -g`, `bun install -g`, `npx --package=` ad-hoc.

A "clean" run = freshly-imaged macOS VM (or `rm -rf ~/.bun ~/.npm-global ~/.cerefox` on the maintainer's machine).

### 12.1 `cerefox web` boot — three modes (24A acceptance)

- [ ] **Mode 1 (source)**: `bun packages/memory/src/bin/cerefox.ts web
      --port 18001` boots; `curl /api/v1/version` returns the version
      JSON; `http://127.0.0.1:18001/app/` loads the React SPA from the
      repo's `frontend/dist/`.
- [ ] **Mode 2 (built)**: `cd packages/memory && bun run build && node
      dist/bin/cerefox.js web --port 18002` boots; SPA served from
      `packages/memory/dist/frontend/`; `/api/v1/version` matches.
- [ ] **Mode 3 (mixed)**: from source bin, SPA falls back to repo's
      `frontend/dist/` when `packages/memory/dist/frontend/` doesn't
      exist; the maintainer can iterate on the Hono server without
      rebuilding the package.
- [ ] `curl /app/assets/index-*.js` returns `Content-Type:
      text/javascript`, NOT `text/html` (R5 — asset middleware wins
      over the SPA catch-all).

### 12.2 Hono routes — actual HTTP-boundary coverage

**Correction (2026-05-28, pre-cut)**: the original framing in this
section ("`uv run pytest -m e2e` covers parity at the `/api/v1/*` HTTP
boundary") was a misread of what `tests/e2e/test_api_e2e.py` does — it
talks to Supabase directly via `CerefoxClient` and never exercises
Hono routes over HTTP. The pre-cut v0.6 follow-up commit added real
HTTP-boundary coverage; pytest still has its place for DB-layer
regressions but doesn't validate the new TS routes. See design doc
§ 19 "Test migration policy" for the durable rule.

What to actually walk:

- [ ] **DB-layer baseline**: `uv run pytest -m e2e -x` (anywhere — the
      tests bypass the local web). Confirms nothing broke at the
      Supabase / RPC / EF / remote-MCP layers. Doesn't validate Hono.
- [ ] **TS HTTP-boundary tests**: `cd packages/memory && bun test
      web-integration` against the live Supabase via the running TS
      web (probe-and-skip when unreachable). Exercises the 5
      destructive endpoints + meta endpoints end-to-end.
- [ ] **Browser walk**: open `http://127.0.0.1:8000/app/` in a
      browser. Dashboard, search, audit log, projects, analytics
      pages all load and render real data. Click into a document,
      verify chunks + versions + review-status toggle work. This is
      the only layer that actually exercises the Hono read routes
      under React Query, since the Playwright UI suite (still
      Python through v0.8) doesn't yet have v0.6-specific
      assertions.
- [ ] **Side-by-side spot check** (optional, only if you suspect a
      shape divergence): start the Python web on :8001, the TS web
      on :8000, diff `curl /api/v1/dashboard` output between them
      (after normalising volatile fields).

### 12.6 Configure-agent Phase 2 (24K)

For each writer, walk against a real client config file (the

- [ ] **Cursor**: `cerefox configure-agent --tool cursor --dry-run

- [ ] **Codex**: `cerefox configure-agent --tool codex` writes TOML

- [ ] **Gemini**: `cerefox configure-agent --tool gemini` writes
